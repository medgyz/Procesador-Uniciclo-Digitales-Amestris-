\section{Descripción General de los Componentes}
En esta primera etapa del proyecto final, se diseñaron, implementaron y verificaron funcionalmente los módulos digitales en SystemVerilog. Los componentes desarrollados son:

\begin{itemize}
    \item \textbf{Unidad Lógica Aritmética (\texttt{alu.sv}):} Módulo combinacional de 32 bits encargado de las operaciones aritméticas y lógicas (\texttt{ADD}, \texttt{SUB}, \texttt{AND}, \texttt{OR}), generando la bandera \texttt{Zero} cuando el resultado es igual a cero.
    \item \textbf{Banco de Registros (\texttt{register\_file.sv}):} Arreglo de 32 registros de 32 bits con dos puertos de lectura asíncrona y un puerto de escritura síncrona habilitado por la señal \texttt{RegWrite}.
    \item \textbf{Generador de Inmediatos (\texttt{imm\_gen.sv}):} Módulo encargado de extraer y reconstruir los inmediatos que vienen de las instrucciones, haciendo la extensión de signo a 32 bits para formatos I-type y S-type.
    \item \textbf{Multiplexor 2:1 (\texttt{mux.sv}):} Selector diseñado para el enrutamiento y selección de datos dentro del datapath.
\end{itemize}

% ==========================================
% 2. DECISIONES PRINCIPALES DE DISEÑO
% ==========================================
\section{Decisiones Principales de Diseño}

\subsection{Unidad Lógica Aritmética (ALU)}
La ALU fue implementada mediante un bloque combinacional \texttt{always\_comb} que evalúa el código de operación \texttt{ALUControl} de 4 bits. La señal \texttt{Zero} se implementó combinacionalmente comprobando si el bus del resultado equivale a cero (\texttt{assign Zero = (Result == 32'b0)}).

\subsection{Banco de Registros e Inviolabilidad de $x0$}
Para asegurarn que el registro $x0$ siempre esté en cero sin importar los intentos de escritura, se añadió una condición de validación en la lógica síncrona:
\begin{verbatim}
always_ff @(posedge clk) begin
    if (RegWrite && (A3 != 5'd0))
        registers[A3] <= WD3;
end
\end{verbatim}
Las lecturas en los puertos \texttt{RD1} y \texttt{RD2} son asíncronas y retornan \texttt{32'b0} si se direcciona $x0$.

\subsection{Generador de Inmediatos}
Se implementó un multiplexor interno controlado por la señal \texttt{ImmSrc}:
\begin{itemize}
    \item \textbf{ImmSrc = 00 (I-type):} Concatenación de \texttt{\{\{20\{instr[31]\}\}, instr[31:20]\}}.
    \item \textbf{ImmSrc = 01 (S-type):} Concatenación de \texttt{\{\{20\{instr[31]\}\}, instr[31:25], instr[11:7]\}}.
\end{itemize}

\section{Verificación}
Cada componente posee un testbench autocontenido (\texttt{*\_tb.sv}) que usa estímulos de prueba y valida de forma automática el valor esperado contra el obtenido, imprimiendo en la consola el estado de \texttt{PASS} o \texttt{FAIL}.

% 5. PROBLEMAS ENCONTRADOS Y SOLUCIONES
% ==========================================
\section{Problemas Encontrados y Soluciones}
\begin{itemize}
    \item \textbf{Escritura involuntaria en la dirección $x0$:} Inicialmente, los valores dirigidos a $x0$ modificaban la posición 0 del arreglo. Se solucionó añadiendo la condición de guarda \texttt{A3 != 5'd0} en la habilitación de escritura.
    \item \textbf{Manejo de extensión de signo en inmediatos negativos:} Habían dudas al mapear el bit de signo de instrucciones S-type. Se resolvió fijando la concatenación explícita con repetición del bit \texttt{instr[31]} de acuerdo con la especificación RISC-V RV32I.
\end{itemize}

% ==========================================
% 6. CONCLUSIONES
% ==========================================
\section{Conclusiones}
\begin{itemize}
    \item Se diseñaron e implementaron con éxito los cuatro módulos base (\texttt{alu}, \texttt{register\_file}, \texttt{imm\_gen} y \texttt{mux}) en SystemVerilog.
    \item La verificación automática en los testbenches permitió confirmar que no habían errores en las operaciones lógicas, aritméticas, almacenamiento de registros y extensiones de signo.
    \item Los cimientos del procesador se encuentran completamente probados, documentados y listos para integrarse en el datapath.
\end{itemize}
